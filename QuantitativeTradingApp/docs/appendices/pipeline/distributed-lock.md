# 附录 · 流水线 · 分布式锁

> 主文档：../../design.md · 版本随 v0.5 同步

## 目的

保证同一时刻只有一个实例执行每日流水线（多实例部署 / 手动触发与定时任务并发时）。

## 获取

- 流水线第 1 步：尝试获取 Redis 锁。
- 失败 → 本轮跳过（另一实例已执行）。

## 释放（必须用 Lua 原子释放）

释放锁时必须校验持有者身份，防止误删他人锁（锁超时后旧持有者恢复执行产生的脑裂问题）。

```lua
-- KEYS[1] = lock key
-- ARGV[1] = run_id（持有者标记）
-- ARGV[2] = TTL
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
```

- 仅当 key 的 value 等于本次运行携带的 `run_id` 时才 `del`，否则不删除。
- 流水线第 9 步调用，保证释放动作与校验原子不可分割。

## 锁超时与监控

- 锁带 TTL（7200s 阈值）。
- 锁超时脑裂已通过 Lua 校验 value 原子释放缓解。
- 仍需监控单次任务耗时，避免接近 7200s 超时阈值（任务过慢可能被另一实例抢占）。
