# 附录 · 风险登记表

> 主文档：../../design.md · 版本随 v0.5 同步

| 事项 | 说明 |
|---|---|
| akshare 接口稳定性 | 接口偶发变动/限流，需监控与降级验证 |
| 全市场拉取时长 | 10-30 分钟，需在 17:00 后留有足够窗口；接口速率受限时动态限速 |
| ST/退市股 | 需持续维护股票状态过滤 |
| 策略有效性 | 策略参数基于历史经验设定，需后续引入回测验证与参数调优（不在本期范围） |
| 个性化建议有效性 | 5% 单股仓位、加仓/清仓规则为经验值，需后续回测与调优；本期作为产品化规则输出 |
| 持仓数据准确性 | 个性化建议依赖用户录入的持仓/资金，准确性由用户负责，前端录入时需校验（股数 > 0、股票存在） |
| Celery 迁移 | 已抽离 `run_pipeline_core` 纯计算函数，状态更新职责随 Worker 迁移，防止异步状态错乱（见 [流水线](../pipeline/overview.md)） |
| 锁超时脑裂 | 已通过 Lua 校验 value 原子释放缓解；仍需监控单次任务耗时，避免接近 7200s 锁超时阈值（见 [分布式锁](../pipeline/distributed-lock.md)） |
| Redis 可用性 | JWT 黑名单、分布式锁、限流均依赖 Redis，需持久化配置与监控告警（数据可重建，容忍短暂不可用） |
| 内存峰值 | 模块二已通过逐股流式处理约束在 200MB 以内；模块三为内存批量计算，需监控单日推荐量级（见 [流水线](../pipeline/overview.md)） |
| 限流 IP 识别 | 依赖 Nginx 透传 X-Forwarded-For 且应用层正确信任，配置错误将导致限流失效或误伤（见 [限流](../api/rate-limiting.md)） |
